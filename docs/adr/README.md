# Architecture decision records

One file per decision that is hard to reverse or would surprise a new
engineer. Status is Accepted unless noted. Supersede, don't edit: write a new
ADR and mark the old one superseded.

| [0024](0024-app-bridge.md) | An app is a principal its manifest bounds: glassd's app socket (uid-authorized, app methods only) runs each call through the agent pipeline, "by [app] for [user]"; undeclared actions are refused and audited; a user-level bridge serves the page (loopback dev mode only, for now). 0023 is on the admin console's branch |
| [0025](0025-native-first-party-apps.md) | Terminal and Activity Monitor are native apps (UI-6) on `glass-window`: iced views in Wayland windows, keys through the compositor's keymap; other first-party apps stay web apps |
| [0026](0026-signed-software-and-verified-execution.md) | Proposed: only signed software runs through `mac_veriexec` (not in 15.1's GENERIC or base, so it needs our own kernel, loader and veriexec builds, BS-2). Each image carries a signed manifest of everything executable; catalog items carry publisher- or org-signed manifests. Keys by purpose under an offline root; unsigned code runs only in the developer VM (DW-1) |
| [0027](0027-web-runtime-on-the-device.md) | The browser engine on the device is FreeBSD's Chromium package by its files (and only the libraries they link, `third-party.py`) until our own build; software drawing; the Browser and the apps keep separate profiles; the app bridge runs per person on their own loopback port and answers only sockets the kernel says are theirs (supersedes 0024's Unix socket for now); our frame on every window; LGPL, MPL and GPL-2.0 libraries ship with the source offer, (L)GPL-3.0 never |
| [0028](0028-remote-help.md) | Remote help's tiers are policy (`[support]` roles mapping directory groups to tools and reach); support staff sign in to the console by role and reach only support routes (every other route needs admin); sessions are one-time offers signed by the console, checked by the device against its own policy, asked of the person with a banner while connected, end-to-end encrypted between the device and the support person's browser (GT-3), audited on both sides as events; unattended access by device types IT sets in the console |
| [0029](0029-device-settings-per-group.md) | Device settings are policy, per group: one table of settings, each set as a default or locked; the higher group wins, then everyone, then the table; the browser's are the whole computer's and set for everyone |
| [0030](0030-chat-and-meetings.md) | Chat and meetings: each conversation's keys sealed to its members' computers and to a compliance key IT keeps itself; glassd opens chat and agents read it through actions (post asks); our servers store ciphertext and metadata; meetings are SFrame-sealed media through our own relay (str0m), never recorded. Built in slices C1–C4, M1–M3 |
| [0031](0031-the-seat-and-settings-computers-apply.md) | Accepted: glassd knows the seat (who is signed in at the screen, from the sign-in screen's `su`, checked by the kernel's peer pid); settings a computer applies itself (sleep, blank, time zone, USB drives) follow whoever is signed in, per group, or the whole computer's from everyone |
| [0032](0032-remix-and-share.md) | Proposed: every web app ships its source; a remix is the person's own app with a base and a diff, checked, bundled and versioned by glassd, never wider than its creator and never with its base's tiers; the store is the only way between people (the console re-runs the checks and shows the diff and the privilege delta); suggestions flow back to owners; store first, remix second, build third, enforced; every personal app is in IT's inventory |
| [0033](0033-shared-space-and-artifacts.md) | Accepted: what people make together (artifacts, docs, sheets, app data) is a sealed chat conversation of its own kind; large content is sealed blobs whose keys travel only in sealed messages; the console stores ciphertext and the metadata IT needs; an artifact is served on its own origin under a CSP sandbox with no network, never downloaded; feedback is messages |
