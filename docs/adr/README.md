# Architecture decision records

One file per decision that is hard to reverse or would surprise a new
engineer. Status is Accepted unless noted. Supersede, don't edit: write a new
ADR and mark the old one superseded.

| # | Decision |
|---|---|
| [0001](0001-rust-workspace-layering.md) | One Rust workspace, layered lib → svc → bin (apps layer added by 0013) |
| [0002](0002-freebsd-release-overlay.md) | Build on unmodified FreeBSD 15.1 releases plus our overlay; develop in a QEMU VM |
| [0003](0003-single-daemon-for-prototype.md) | One privileged daemon hosting services as libraries, for now |
| [0004](0004-mcp-over-task-sockets.md) | Agents speak MCP over a per-task Unix socket; JSON-RPC everywhere |
| [0005](0005-brokered-file-access.md) | Agents get no user data mounted; file access is brokered |
| [0006](0006-file-level-undo.md) | Undo restores files from snapshots, never rolls back datasets (superseded in part by 0017) |
| [0007](0007-drive-freebsd-through-admin-commands.md) | Drive jails and ZFS through their admin commands |
| [0008](0008-agent-manifests-declare-privileges.md) | Proposed: agents ship signed manifests; effective rights = declaration ∩ policy ∩ scope |
| [0009](0009-native-shell-web-apps.md) | A native Rust shell on Smithay and iced; apps are TypeScript web apps |
| [0010](0010-agents-are-harness-bundles.md) | Proposed: agents are versioned harness bundles run by one runner; hard limits stay in the OS |
| [0011](0011-branding-on-a-freebsd-base.md) | Branding: overlay now (tested), our own base build next; notices and SBOM generated from the build |
| [0012](0012-system-actions-broker-role.md) | IT self-service runs as fixed-function system actions in glassd; policy is the broker role |
| [0013](0013-one-crate-per-app.md) | One crate per app's actions, built against a lib-layer contract; layers lib → apps → svc → bin |
| [0014](0014-tailoring-layers.md) | Tailoring is a stack of personal layers glassd checks and applies; layers only narrow, every change is a version |
| [0015](0015-take-over-in-your-harness.md) | Take over on an ended actions agent continues the task in the user's harness (Claude Code through `glass-mcp`); attended agents |
| [0016](0016-showing-the-shell.md) | The shell shows on the console framebuffer in the VM (verified, with evdev input) and through DRM on hardware; one compositor, two outputs |
| [0017](0017-undo-from-change-records.md) | Undo restores only the files the task changed, from its change records; a file changed since is left and reported; take-over edits are changes |
| [0018](0018-model-gateway.md) | glassd brokers every model call: `model_complete` is an action routed by the labels the task has read, redacted, audited without prompt text; HTTPS on the base system's OpenSSL; secrets in a root-only file until the broker exists |
| [0019](0019-signing-in.md) | Accepted: a greeter on the screen signs people in through PAM and starts their desktop with `su -l` |
| [0020](0020-agents-that-may-run-elsewhere.md) | Proposed: agents may later run in the cloud with local hands; the task socket stays the only interface and task state stays data (FD-1 to FD-4) |
| [0021](0021-managed-settings-load-from-disk.md) | Managed settings never block boot: glassd starts from the policy on disk, checked once, falling back to the last good one; new settings are fetched in the background and applied whole (fetch and live apply proposed) |
| [0022](0022-build-on-pkgbase.md) | Accepted: build on pkgbase; an image is a list of packages from one repository, ours included; devices take whole images; FreeBSD stays behind `glass-platform` |
| [0023](0023-admin-console-and-signed-sync.md) | Accepted: the admin console is a web app on our servers (`glass-console`, `apps/console`); policy and catalog releases are signed with the org's ed25519 key; devices verify, validate whole and apply them in the background, keep working offline, and report; which apps a person gets is policy by role, enforced by glassd; org apps never go public; `catalog.search` scopes by the user's groups |
| [0024](0024-app-bridge.md) | An app is a principal its manifest bounds: glassd's app socket (uid-authorized, app methods only) runs each call through the agent pipeline, "by [app] for [user]"; undeclared actions are refused and audited; a user-level bridge serves the page (loopback dev mode only, for now). 0023 is on the admin console's branch |
| [0025](0025-native-first-party-apps.md) | Terminal and Activity Monitor are native apps (UI-6) on `glass-window`: iced views in Wayland windows, keys through the compositor's keymap; other first-party apps stay web apps |
| [0026](0026-signed-software-and-verified-execution.md) | Proposed: only signed software runs through `mac_veriexec` (not in 15.1's GENERIC or base, so it needs our own kernel, loader and veriexec builds, BS-2). Each image carries a signed manifest of everything executable; catalog items carry publisher- or org-signed manifests. Keys by purpose under an offline root; unsigned code runs only in the developer VM (DW-1) |
| [0027](0027-web-runtime-on-the-device.md) | The browser engine on the device is FreeBSD's Chromium package by its files (and only the libraries they link, `third-party.py`) until our own build; software drawing; the Browser and the apps keep separate profiles; the app bridge runs per person on their own loopback port and answers only sockets the kernel says are theirs (supersedes 0024's Unix socket for now); our frame on every window; LGPL, MPL and GPL-2.0 libraries ship with the source offer, (L)GPL-3.0 never |
| [0028](0028-remote-help.md) | Remote help's tiers are policy (`[support]` roles mapping directory groups to tools and reach); support staff sign in to the console by role and reach only support routes (every other route needs admin); sessions are one-time offers signed by the console, checked by the device against its own policy, asked of the person with a banner while connected, end-to-end encrypted between the device and the support person's browser (GT-3), audited on both sides as events; unattended access by device types IT sets in the console |
| [0029](0029-device-settings-per-group.md) | Device settings are policy, per group: one table of settings, each set as a default or locked; the higher group wins, then everyone, then the table; the browser's are the whole computer's and set for everyone |
| [0030](0030-chat-and-meetings.md) | Chat and meetings: each conversation's keys sealed to its members' computers and to a compliance key IT keeps itself; glassd opens chat and agents read it through actions (post asks); our servers store ciphertext and metadata; meetings are SFrame-sealed media through our own relay (str0m), never recorded. Built in slices C1–C4, M1–M3 |
| [0031](0031-the-seat-and-settings-computers-apply.md) | Accepted: glassd knows the seat (who is signed in at the screen, from the sign-in screen's `su`, checked by the kernel's peer pid); settings a computer applies itself (sleep, blank, time zone, USB drives) follow whoever is signed in, per group, or the whole computer's from everyone |
| [0032](0032-remix-and-share.md) | Proposed: every web app ships its source; a remix is the person's own app with a base and a diff, checked, bundled and versioned by glassd, never wider than its creator and never with its base's tiers; the store is the only way between people (the console re-runs the checks and shows the diff and the privilege delta); suggestions flow back to owners; store first, remix second, build third, enforced; every personal app is in IT's inventory |
| [0033](0033-shared-space-and-artifacts.md) | Accepted: what people make together (artifacts, docs, sheets, app data) is a sealed chat conversation of its own kind; large content is sealed blobs whose keys travel only in sealed messages; the console stores ciphertext and the metadata IT needs; an artifact is served on its own origin under a CSP sandbox with no network, never downloaded; feedback is messages |
| [0034](0034-skills-versioned-and-evaluated.md) | Accepted: a skill is a shared-space item whose versions are sealed bundles with their evals; evals run as a jailed agent's task through the model gateway; proposals carry before and after scores from one run; the owner merges, with a reason when a case breaks; items carry labels that raise a reading task's; apps may start the agents their manifest names; agents use pinned versions mounted read-only |
| [0035](0035-docs-and-sheets.md) | Accepted: docs and sheets are shared-space items holding one Yjs document each (yrs on the computer); live edits flow over an audited-once editing session (`app.live`), not per-keystroke actions; items keep their own logs locally, compacted by snapshots; agents read Markdown and computed values; one formula engine of ours, native and wasm; apps may ask for models; writes ask until a provider undo hook can revert them |
| [0036](0036-developer-tools-from-the-store.md) | Proposed: developer tools are catalog items for people with developer mode; they install from the org's signed mirror into the person's developer jail, never the base, one root per version with a shim that follows the project's pin file; Linux-only tools (Microsoft's VS Code, GitHub Desktop, nvm) wait for the Linux workspace |
| [0037](0037-glasshouse-mail.md) | Accepted (2026-10-20): Glasshouse Mail (EM-1 to EM-4) is a mox server per org (MIT) on our AWS, each with its own volume, KMS key and IP; outbound through SES with a tenant per org, inbound straight to the cell; the console runs domains and DNS checks; the computer reaches it through the same mail actions over IMAP and SMTP. GT-3 gains its mail exception (placement A for pilots, only for orgs with no mail); journal sealed to the compliance key; Spamhaus on its paid service; we run the on-call. Stalwart is out (AGPL) |
| [0038](0038-the-owner-of-a-computer-no-organization-manages.md) | Accepted (2026-10-20): a computer no organization manages has an owner, the account first-run setup made (recorded in setup.toml; else the first person's); the owner sets the computer's own settings (device and seat) for everyone on it, kept root only apart from each person's; one resolution (locked, owner, policy default, built-in) for what Settings shows and what glassd applies; glassd marks what each person may change; never an agent |
| [0039](0039-model-credits-through-openrouter.md) | Accepted (2026-10-20): orgs without Bedrock or their own key buy model credits from us, routed by OpenRouter's auto router; one OpenRouter key per org, made by the console with our management key and capped at what it bought, kept on our servers; computers send calls on credits to the console, signed with their own keys, and it forwards them (amending ADR 0018 for credits), keeping only who called, tokens and cost, and asking only for providers that keep no data; turning credits on is a policy edit; confidential data stays off it unless IT routes it; admins pay by card through Stripe (signed webhooks, once per session) at our markup, taken off the key's limit, after accepting the providers' terms; individuals use the same provider with their own key. |
| [0040](0040-the-billing-relay.md) | Accepted (2026-10-21): one Stripe webhook endpoint for every org, `glass-billing` on our servers: checks Stripe's signature, queues each paid checkout on disk for the console of the org it names, and pushes it there signed with its own P-256 key, retried until taken (dead after three days, resendable by our operators); consoles ask it for checkouts with their own token, so Stripe's secret key is on the relay alone; a console takes payments from the relay or, alone on a Stripe account, from Stripe, never both |
| [0041](0041-tool-use-through-the-gateway.md) | Proposed, built (2026-10-21; two choices await the owner): `model_complete` takes tools and returns tool calls; the model proposes, the task socket decides (every rule applies to the call the agent then makes); tool inputs and results are redacted like text and recorded only as counts; each provider maps it; `glass-desktop-agent` is a first general agent on it (AE-3) |
| [0042](0042-the-desktop-agent-on-your-own-claude-code.md) | On hold (2026-10-22, for ADR 0043); first slice built (2026-10-21): the desktop agent on the person's own Claude Code and Claude plan; Glasshouse launches their unmodified, signed-in Claude Code as them (`glass-claude-runner`, run by their client, never glassd) with only the task socket's tools, proven by its first event, and never touches their sign-in; internal data at most (HX-7); no FreeBSD build of Claude Code yet; needs Anthropic's confirmation before shipping |
| [0043](0043-anthropics-api-in-our-own-harness.md) | Accepted, built (2026-10-22): Anthropic's current models in our own harness. The model's own blocks (thinking included) go back to it through the agent, sealed by the gateway and never redacted again; prompt caching, with cache reads and writes on the record and priced; refusals end the call on the record; 16,000-token output default; Settings refuses Claude sign-in tokens; an owner's default is Claude Opus 5.5 |
| [0044](0044-start-cheap-and-let-repeats-become-scripts.md) | Accepted, built (2026-10-22): agents may ask `model.complete` for the cheapest or strongest model a call's data may go to where policy says (`[models] by_cost`); the desktop agent starts on the cheapest and climbs one step at a time (Haiku to Sonnet to Opus); exact work goes to scripts the agent writes and runs in its jail (`run_script`, `glass-script` on Boa), whose only reach is the task's tools; routines (DA-4) are such scripts saved with the task's scope, approved script and all, and run with no model when started or on a schedule, the model taking over when one breaks (NV-21) |
| [0045](0045-meeting-transcripts-and-agents-in-meetings.md) | Accepted, not built yet (2026-10-22): IT turns meeting transcripts on per group; each computer transcribes only its own person's microphone, on the computer, into the meeting's sealed conversation (IT's compliance key, retention, holds); agents read it but still can't join; only the person's own "Hey Glass…" starts their desktop agent, whose sends still ask |
